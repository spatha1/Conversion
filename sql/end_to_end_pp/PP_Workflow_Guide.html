PP Conversion · Pilot Run Guide

PP End-to-End Pipeline — Steps 0–10

Every script needed to take a pilot batch of Personal Protection policies from Pure through Party creation, policy XML generation, the DCT push, and back into Clarity for reconciliation. Run in order — each step's output feeds the next. Nothing here has been executed. Read a step's explanation before running its code.

How this maps to the system

Two systems do the work: Snowflake (AGGNE.DEV) generates XML and holds the read models; SQL Server (Capricorn-Dev-SwiftConversion) owns the request/response queue (PSD.Configdata) that an existing Timer Trigger polls and pushes to DCT. Steps alternate between the two — each card below says which.

What changed from the original 10-step plan:
  • Step 0 added — global kill-switch check, backlog sanity check, and a fixed pilot policy list. Nothing runs against full DEV volume until this pilot proves out.
  • Party push is DEV-scoped, not the existing UAT one. The proven procedure writes to AGGNE.UAT — but policy conversion reads {PARTYID} from DEV's own tables. Step 2 is a new, DEV-targeted copy.
  • Step 3 needs new infrastructure. The Timer Trigger's 10 Process_N views only poll ConfigrequestId IN (33,35,17,42) today. Step 3 registers a new config row and adds it to 9 of those views — the DDL step worth gating behind a password in the future UI.
  • Step 6 bypasses HB_PP_PolicyConversion_LoadViews. That SP calls udf_generate_configdata 16 — 16 is BP_ConfigRequest, not PP (confirmed bug). Config 42 (PP_CreatePolicy) is already polled, so Step 6 queues into it directly.
  • Step 5 gates on validation instead of deferring it — SP_PP_XML_VALIDATE already exists and runs before Step 6 can push anything to DCT.
  • Step 7 is intentionally incomplete. The Timer Trigger already calls DCT for PP (388/430 historically processed) — nothing parses the response into RESULTS_JSON yet. One real response body is needed before that parser can be written accurately.
Still needed before running Steps 3 and 6:
  • The Snowflake linked-server name used in OPENQUERY([<SNOWFLAKE_LINKED_SERVER_NAME>], ...)
  • One real raw DCT response body for a processed PP policy (unlocks Step 7's parser)
  • PP_Policy_Request_Load_v1's actual columns — Step 6 has a precheck query for this
  • The pilot policy list itself (Step 0) — 5–10 policies, including one from the known-good 38-policy UAT batch
STEP 0

Safety check & pilot scope

STEP0_SAFETY_AND_PILOT_SCOPE.sql

SQL Server read-only + DDL (pilot table) depends on: nothing

STEP 1

Identify missing CMLs

STEP1_IDENTIFY_MISSING_CMLS.sql

Snowflake read-only depends on: Step 0

A PP policy's CML must already have a resolved PartyId (via the proven VW_PARTYDET chain) before policy conversion can send a correct {PARTYID} token. This finds which pilot CMLs still need a Party push.

STEP1_IDENTIFY_MISSING_CMLS.sql 
-- ============================================================
-- STEP 1 — Identify missing CMLs for pilot PP policies
-- Run on: Snowflake, AGGNE.DEV (id=14 connection)
-- Type: READ-ONLY
--
-- Logic: a PP policy's CML must already have a resolved PartyId
-- (via the proven VW_PARTYDET chain) before policy conversion can
-- send a correct {PARTYID} token. This finds CMLs with no PartyId
-- yet, scoped to the pilot list from Step 0.
-- ============================================================

SELECT DISTINCT
    P.LEGACYPOLICYNUMBER,
    P.CMLNUMBER,
    V.PARTYID,
    CASE WHEN V.PARTYID IS NULL THEN 'MISSING — needs Party push'
         ELSE 'OK — PartyId already resolved' END AS STATUS
FROM AGGNE.DEV.PP_PILOT_POLICIES P                 -- from Step 0
LEFT JOIN AGGNE.DEV.VW_MAX_PARTYDET V
       ON TRIM(P.CMLNUMBER) = TRIM(V.CML_NUMBER)
ORDER BY STATUS DESC, P.LEGACYPOLICYNUMBER;

-- Summary count
SELECT
    SUM(CASE WHEN V.PARTYID IS NULL THEN 1 ELSE 0 END) AS MISSING_CMLS,
    SUM(CASE WHEN V.PARTYID IS NOT NULL THEN 1 ELSE 0 END) AS RESOLVED_CMLS,
    COUNT(DISTINCT P.CMLNUMBER) AS TOTAL_DISTINCT_CMLS
FROM AGGNE.DEV.PP_PILOT_POLICIES P
LEFT JOIN AGGNE.DEV.VW_MAX_PARTYDET V
       ON TRIM(P.CMLNUMBER) = TRIM(V.CML_NUMBER);

-- Take the MISSING CMLNUMBER list from the query above into Step 2's filter.
