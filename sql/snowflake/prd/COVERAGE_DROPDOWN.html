Policy Attach Pipeline — 7 Steps (BP; PP mirrors same structure)

Step Name SP / Script Location Notes
1Pure To WriteAGGNE.PRD.SP_POLCIY_ATTACH_PURE_TO_WRITE_LOADSnowflake PRDExtracts all PURE source tables into PRD _POLICYATTACH staging tables
2DateDim & Identifier SetupAGGNE.PRD.SP_Datedim_Identifier_SetupSnowflake PRDBuilds start‑date‑to‑end‑date DOL combinations per policy (~10 per policy). Any future DOL fits one combination. Re‑runs if new transactions arrive.
3Load ViewsHB_BP_PolicyAttach_LoadViews
↳ PolicyAttach_LoadViews_and_LoadBucket		Conversion DBLoads config source tables into Snowflake views (the _IDENTIFIER + sub-coverage views)
4Final Data LoadAGGNE.PRD.LOAD_PA_BP_FINAL_OUPUTSnowflake PRDCalls DYNAMIC_XML_V1 per config row; writes XML into *_TARGET tables; assembles into PRD_XML final table
5Final XML LoadAGGNE.PRD.POLICYATTACH_LOAD_FINALDATA_XMLSnowflake PRDLoads XML data into PRD_XML.POLICYATTACH_MIGRATION_DCT final table
6Final Run (DCT)PolicyAttach_FinalRun
↳ POLICYATTACH_UAT_BUCKET
↳ PolicyAttach_PRD_Request_Load_V1		Conversion DBGets identifier + bucket from final table; POSTs DCT request with LegacyPolicyNumber + DOL per combination
7Load API TableAGGNE.PRD.Load_PolicyAttach_API_TableSnowflake PRDLoads DCT API response from XML table into API response table for tracking
DOL Combination Design: Each policy generates ~10 start‑to‑end date combinations (Step 2) so any future Date of Loss falls within one. If a new transaction is added, Step 2 regenerates all combinations for that policy to cover the new DOL. This avoids re‑running attach for every new DOL individually.
